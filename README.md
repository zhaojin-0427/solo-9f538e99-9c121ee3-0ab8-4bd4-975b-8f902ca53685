# 设备巡检记录管理

Flask + SQLite 的巡检记录网站。表版（巡检表版本）登记后不可修改；上传 CSV
后逐条记录判定，并提供记录查询与单项答案更正。

## 快速启动

```bash
docker compose up --build
```

打开 <http://localhost:8000>。SQLite 数据保存在命名卷 `inspection-data`
（容器内 `/data/inspection.db`），重启或重建容器后仍在。

也可以直接运行：

```bash
python3 -m pip install -r requirements.txt
DATABASE=./data/inspection.db python3 -m flask --app app run
```

## 使用流程

1. **登记表版**（不可改）。每行一个检查项，最多 12 项：

   ```
   冷却泵已安装
   备用泵外观检查 | 1=是
   备用泵压力检查 | 1=是 & 2=是
   安全阀检查
   ```

   * 只写名称的项**始终显示**。
   * `名称 | 条件`：`1=是` 引用第 1 个检查项；`&` 表示组内全部满足，
     `;` 分隔多组，任一组满足即显示。
   * 条件只能引用排在前面的检查项。全角 `＝＆；` 也可识别。
   * 没装冷却泵的机台不检查备用泵：把“冷却泵已安装”设为条件，
     备用泵各项写 `1=是` 即可。

2. **上传 CSV**。表头需含“记录号”及本版全部检查项名称；每格填
   `是`、`否` 或留空。最多 50,000 条，单表版只能导入一次；整份文件
   校验失败时不写入任何记录。支持 UTF-8（含 BOM）和 GB18030。

3. **查看计数**。表版页按检查项显示已保存的已答、漏填、免检、待核四类计数。

4. **按记录号查看并更正**。记录页显示每项答案与判定，可在下拉框更改
   一项答案。更正只重判该条记录，答案、判定和计数在同一事务中保存；
   成功当次即显示新判定与计数，失败则三者都不变（重启后依然如此）。

5. **规则覆盖分析**。表版导入记录后，从首页或顶部导航进入“规则覆盖分析”，
   选择表版后点“开始分析”。分析完全只读，不改变表版、答案与四类判定。

   * 每个检查项的每个条件组按记录统计“满足 / 排除 / 无法确定”三种状态：
     满足指所有补答情形下该组都成立，排除指都不成立，无法确定指是否成立
     取决于留空项补答。
   * 列出“从未可满足的条件组”，给出快照中的记录数，并在明细页逐条列出
     记录号与依据。
   * 列出“同一记录可能命中多个条件组”的检查项：同一记录在不同补答下可
     满足两个及以上条件组时需人工确认。
   * 计数与明细都来自同一次读取的快照；之后若有答案更正，页面会提示
     “请重新分析”，旧快照的明细仍可查看但标为过期。分析过程中发生更正
     时，本次结果不会保存。
   * 点击检查项进入明细页，可按条件组、状态、记录号筛选，逐条查看每个
     条件组成立或不成立的原因。

## 判定规则

留空的显示项按“补答是”与“补答否”两种可能分别推演；同一项在每种补法里
只取一个值。隐藏项上的残留答案不参与判断。于是每项归入：

| 类别 | 含义 |
| ---- | ---- |
| 已答 | 始终显示且原答案填了是/否 |
| 漏填 | 始终显示但原答案留空 |
| 免检 | 所有补答情形下都不显示 |
| 待核 | 是否显示取决于留空项，需要回头核实 |

## 测试

```bash
python3 -m pytest
```

测试覆盖解析、判定（含与穷举实现交叉验证）、CSV 校验、50,000 条导入、
更正事务回滚与重启后一致性，以及规则覆盖分析（条件组状态与穷举对照、
快照对齐、分析期间更正不落库、过期提示、明细筛选与分页）。
